# 6 · 地点搜索

`app/placeSearch.ts`（605 行）。文件顶部注释（约 1–45 行）记录了**九条实测结论**，
是整个模块设计的地基，接手人必读。核心问题：**Mapbox 的 POI 索引没有中文名** ——
「成田国际机场」原样查回来的是马来西亚民宿，换成「成田空港」第一条就对。

## 6.1 为什么这么绕

| 现象 | 结论 |
| --- | --- |
| POI 索引只有当地文字名 | 中文原样查不中，必须改写 |
| 日文名同字不同形（成田国際空港 vs 成田国际机场） | 需要字形桥 |
| 日文字形缺失时靠拼音桥（"Narita Airport"） | 拉丁名可靠 |
| IATA 码（NRT）查询结果不可用 | 不用码 |
| 大中华区（hk/mo/tw/cn）同名外国小镇会顶掉真正的城市 | 只能按 country 收窄 |
| 收窄后精度上限是城市/区级 | 不要指望 POI 级中文结果 |

所以查询计划是**一次并发查多种「说法」**：原文、日文写法、剥掉通名的专名。
每条结果都记下是哪个说法查出来的 —— `rankHits` 要按它再打一次分，否则
「京都駅」这种改写出来的命中会被原始输入「京都站」扣掉分。

## 6.2 查询改写（queryVariants）

输入 `query` → 最多 5 个变体（`SCRIPTS`、`JA_WORDS`、`JA_CHARS`、`EXONYMS`、`SCOPES`）：

- `minQueryLength`：CJK 1 个字就能搜，拉丁语要 2 个字母。
- `queryLanguage`：语言按用户打的文字选，不按界面语言。
- `stripHubSuffix` + `HUB_SUFFIXES`：剥掉「机场/駅/站/港」这类通名后缀，留下专名
  （长后缀优先）。
- `toJapanese`：中文写法改写成日文写法 —— 通名整词换（「机场」→「空港」），
  字形逐字换（「国」→「国」按日文字形表）。`SCRIPTS` 第二条是日文专用字形 + 「空港」「丁目」。
- `EXONYMS` 别名桥：中文枢纽名换成 Mapbox 真查得到的当地写法（比如中文名 → 当地名）。
- `SCOPES`：大中华区按国家收窄（hk/mo/tw/cn），`scopeOf` 从「用户打的国家名」猜。

`trust` 标记别名桥那一路 —— 它连文字都不沾，打分要走另一条分支（`viaBridge`）。

## 6.3 打分（scoreHit / rankHits）

`strongTier`（140/100/74/55）：强匹配分档；`textTier`：ratio < .34 的弱匹配直接丢掉，
shrink 惩罚。`scoreHit` 的规则（都在测试里验过）：

- **纯通名名字判 0**（整个名字就是一个通名 → 结果直接丢掉）；
- ADMIN_TAIL 再比一次只进强匹配（「东京都」不该被当成「东京」的不匹配字）；
- bloat 惩罚（一堆无关词缀）；类型 +28 / −42；枢纽类目 +46、枢纽名 +24；同类 +30、异类 −42。

`rankHits(hits)`（合并所有变体的结果）：

- 去重键 `name|address前12字`；按查出它的那个说法打分，跨语言才排得对；
- 别名桥的命中不比文字、只验类型（`viaBridge: 210 − min(48, rank×12)`）；
- 同分按 Mapbox 自己的 rank 排，再按有坐标者优先；
- `MAX_HITS = 8`；`stopKindOf`：机场判定排在车站之前（查机场别让旁边那个车站排前面）。

## 6.4 与 page.tsx 的接线

- 300ms 防抖 + `AbortController`（换词即中断旧请求）；
- `suggest`（Search Box）与 `geocode/v6/forward` 两个引擎并发，country 参数只对有 SCOPES
  的变体加；
- 单请求失败只当返回空，不拖垮其他路；
- 点结果时 `retrieve` 换坐标（suggestion 只有 id），顺手带回国家码；
- 地图选点走 `reverse` 一次反查（文档 2 §2.9）。
