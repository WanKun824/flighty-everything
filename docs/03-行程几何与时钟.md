# 3 · 行程几何与时钟

`app/routeGeometry.ts`（363 行）是「站点 → 线形 → 里程 → 时间轴 → 播放时钟」的整条链路，
全部是纯函数加两个 hook。`routeRules.ts`（47 行）是四种交通方式的声明式规则目录。
`timeSync.ts`（19 行）把真实时刻映射到 0–1 行程进度。

## 3.1 各交通方式用什么形状

头注释（5–18 行）是权威说法：

| 方式 | 基准 | 说明 |
| --- | --- | --- |
| 飞机 | 大圆航线（球面 slerp） | 民航计划航路就是以大圆为基准再按航路点修正，本地能算出最接近真实的形状，不需要联网 |
| 轮船 | 大圆 | 近海直航基本贴大圆，港到港短程更是如此 |
| 汽车 | Mapbox Directions `driving` 折线 | 真实路网几何 |
| 火车 | **也是 driving** | Mapbox 没有 rail profile，用真实陆路走廊近似轨道走向 —— 形状来自真实基础设施，但不是真实轨道中心线。**注意与 `routeRules.ts` 的口径差异，见文档 2 §2.11** |

任何一段取不到路网（跨海、超距、离线、限流、token 无 directions 权限）都退回大圆，
线不会断，里程也仍然是球面真值。

`useJourneyPaths(stops, token)`（hook，约 320–363 行附近）为每段请求几何：

```ts
if (leg.mode !== "car" && leg.mode !== "train") continue;   // 只有汽车、火车走路网
```

- 带 7 秒 `AbortController` 超时。
- **3.2 倍合理性闸门**：路网折线比大圆长，但不会长得离谱。如果 `road / geodesic > 3.2`，
  判定这条响应不可信（大圆经过了把路网结果挤成一团的近岸地物，或响应本身有问题），退回大圆。
- `roadCache` 按 `起点|终点|mode` 缓存，换行程、编辑站点时重复请求直接命中。

## 3.2 基础几何（纯函数）

| 函数 | 做什么 |
| --- | --- |
| `haversineKm(a, b)` | 球面距离，单位公里。实测与公开真实航段里程对得上（tests） |
| `bearingDeg(a, b)` | 正北顺时针的初始方位角 |
| `geodesic(a, b)` | 球面 slerp 大圆，96 步。**不是经纬度直线**：大圆中点必须偏离线性中点（tests） |
| `unwrap(coords)` | 跨 ±180 经线展开，避免线段横穿整张地图（tests） |
| `webMercator([lng, lat])` | 投影到平面，供 `cumulativeWeb` 用 |
| `measure(points)` | 同时算 `cumulativeKm`（球面）与 `cumulativeWeb`（平面） |

`sampleAt(path, progress)` 是逐帧驱动的地基（二分 + 同一次采样给三样东西）：

```ts
{ coordinate, bearing, lineProgress } = sampleAt(path, legProgress)
```

- `coordinate`：位置；`bearing`：该点的方位角（逐段常量，顶点间不插值 —— 见文档 2 §2.5 的
  滤波讨论）；`lineProgress`：**墨卡托刻度**（沿 `cumulativeWeb` 线性），不是球面刻度 ——
  `trailGradient` 必须吃这个刻度，否则每段渐变的前进速度不一样。
- 弧长参数化（`cumulativeKm` 上二分）：顶点疏密不均时，进度均匀推进、位移也均匀（tests 专门验了）。

## 3.3 时间轴：压缩到可观看的比例

`buildTimeline`（约 220–280 行）：

- 每段按巡航速度给时长：`cruiseKmh = { flight: 820, car: 78, train: 235, ferry: 34 }`。
- 然后按 `COMPRESSION = .6` 压缩：`hours^0.6` 作为权重 —— 真实行程里飞机占的时间占比巨大
  （飞 2 小时、路面 3 天），不压缩的话 8 小时的汽车段在地球仪上是一闪而过。
  压缩后四段的屏幕时长比例更接近「各自在视觉上的重量」。
- `timeline.legs[i] = { from, to, km }`（0..1 区间），`legs[last]` 收尾到 1。

## 3.4 播放时钟与缩放折算

```ts
export const PLAYBACK_SECONDS = 329;   // 1× = 全程 329 秒
export const ZOOM_REFERENCE = 4.7;     // 基准缩放：这一级上倍速就是名义值
export const zoomRate = (zoom: number) =>
  Math.min(2.5, Math.max(.25, 2 ** (-(zoom - ZOOM_REFERENCE) * .3)));
```

`useJourneyClock(playing, speed, scaleRef)`（316–351 行）：

```ts
// rAF 每帧：
const delta = Math.min(.25, (now - last) / 1000);          // 切走标签页回来截断
const rate = speed * Math.max(.05, scaleRef?.current ?? 1);
progressRef.current = (progressRef.current + delta / (PLAYBACK_SECONDS / rate)) % 1;
```

- **`progressRef` 每帧更新**（60fps 命令式驱动），**`progress` 每 62ms 快照一次**（面板文字和
  进度条不需要 60fps，省掉大量重渲染）。两个刻意分开。
- `scaleRef` 是缩放折算出来的额外倍率，走 ref 不走 state：地图缩放时它每帧都在变，
  做成 state 会把整个探索屏卷进重渲染（313–314 行注释）。
- 换掉原来的 `setInterval(34ms)` 是因为后者跟显示器刷新不同步、持续掉帧抖动，而且每 34ms
  重渲染整个探索屏。
- `zoomRate` 语义与调参理由见文档 2 §2.6。

`locate(timeline, t)`：全程进度 0..1 → `{ legIndex, legProgress }`，越界钳制。

## 3.5 真实时间同步（timeSync.ts + ExploreScreen）

`parseJourneyWindow(start, end)`：两个 `datetime-local` 字符串 → `{ startMs, endMs }`；
`timelineProgressAt(now, start, end)`：当前时刻 → 0..1 进度，两端钳制；
`liveJourneyStatus(progress)`：`waiting` / `traveling` / `arrived`。

ExploreScreen（990–996 行）：

```ts
if (clockMode !== "live" || !liveWindow) return;
const update = () => seek(timelineProgressAt(Date.now(), liveWindow.startMs, liveWindow.endMs));
update();
const timer = window.setInterval(update, 500);
```

切进真实时间模式：先立即归位，再每 500ms 对齐一次。无效时间段（结束早于开始）不会启动同步。

## 3.6 消费者一览

| 谁 | 读什么 | 干什么 |
| --- | --- | --- |
| MapCanvas rAF（文档 2 §2.5） | `progressRef` + `locate` + `sampleAt` | 载具位置/航向/轨迹渐变 |
| 面板 | `progress`（62ms 快照） | 进度条位置、段名、时间读数 |
| `gotoLeg` / `stepLeg` | `timeline.legs[i].from/to` | 跳到第 i 站出发时刻；后退先回本段起点（阈值 .02） |
| 顶部统计 | `paths[i].km` | `totalKm`、`roadLegs`、`transportKinds` —— 全部来自真实线形，路网段沿路累加、大圆段球面真值 |
| `jumpToTransport` | `paths.findIndex(p => p.mode === type)` | 「载具」分段里点机型跳到对应段 |

## 3.7 改这些参数的后果

- `PLAYBACK_SECONDS`：全局手感，等于把所有动画节奏重定一遍（历史：46 → 230 → 329）。
- `COMPRESSION`：段与段的时长比例（飞机 vs 汽车谁的屏幕时间多）。
- `cruiseKmh`：每段「真实感」的权重，顺带影响压缩后的比例。
- `zoomRate` 的指数 `.3`：缩放时速度变化的剧烈程度（1 是完全补偿，千倍级，会甩）。
- 闸门 `3.2`：路网响应「长得离谱」的判定线，误杀率 / 漏杀率在它上面做权衡。
