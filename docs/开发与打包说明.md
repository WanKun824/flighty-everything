# 开发、构建与 GitHub 打包

更新：2026-10-18；应用版本：0.3.2。当前交付以根目录 README、`PACKAGE-VERIFICATION.json` 和本轮 Release 为准。旧日期报告仅作历史参考。

## 1. 项目与环境

React 19 / TypeScript / Vite（vinext）+ Capacitor 8 混合应用。Web、iOS、Android 共享主要界面；iOS 通过 UIKit 桥接玻璃控件、返回手势、安全区和前台定位，不是 SwiftUI 全量实现。

需要 Node.js **>=22.13.0**（CI 使用 Node 22）、npm、Git。源码打包和截图清单工具需要 Python 3.10+（标准库即可）。Windows 可用 `npm.cmd`。

```sh
npm ci
npm run dev
```

按终端提示打开开发服务器。不要在未知情况下执行 `npm audit fix --force` 或升级全部依赖。

## 2. 本地验证

```sh
npm test                                  # 生产构建 + Node 自动测试
npx tsc --noEmit -p tsconfig.json          # TypeScript
npm run native:build                     # Capacitor Web 资源，不是 IPA/APK
npx playwright test                      # 本机 Chrome 交互测试
npm run lint                             # 当前仍有已知规则问题，见交付清单
```

浏览器配置见 `playwright.config.mjs`。默认使用本机 Chrome，必要时设置 `PLAYWRIGHT_CHROME_PATH`。报告位于 `build/ui-acceptance-report/index.html`。测试浏览器隔离于用户日常数据；浏览器测试故意阻断部分外部服务，不能冒充真实网络或原生验收。

## 3. 配置、数据与隐私

- 可参考 `.env.example` 配置 Web 的公开 Mapbox token；只能使用允许公开且限制使用范围的 token。
- 原生构建目前通过 `vite.native.config.ts` 把 `NEXT_PUBLIC_MAPBOX_TOKEN` 设为空，实际使用 `app/mapboxConfig.ts` 的公开备用 token。只修改 `.env.local` 不会替换原生备用 token。
- 地图：Mapbox；天气：Open-Meteo；雷达：RainViewer。机场基础目录：`public/data/airports.json` / OurAirports。机场地点和示例统计不是实时运营通告。
- 航班查询：`/api/transport/flight`；列车：`/api/transport/rail`；网页社区：`/api/community/journeys`，D1 结构见 `db/`、`drizzle/`。原生公开查询通过 `native/transportBridge.ts` 适配。
- 行程、资料、同行示例、收藏和草稿主要保存在本机，不提供自动跨设备备份。清除、卸载或系统清理可能导致丢失。
- 同行是本地演示；原生社区与 Web D1 服务的行为不同，不得宣称真实共享和同步均已验证。
- iOS 使用 `KeyboardResize.None`，由 `useMobileViewport.ts` 合并原生和浏览器键盘 inset；Android 依赖系统调整视口，不重复扣减键盘高度。
- 交付不包含用户记录、生产 D1 数据、签名证书、私有环境文件或访问令牌。

## 4. iOS IPA：GitHub 上构建

Windows 不能运行 Xcode。使用 Actions → **Package iOS Client**，选择本轮交付分支：

| 参数 | 建议值 | 作用 |
| --- | --- | --- |
| `source_sha` | 分支当前完整提交 SHA | 校验实际打包源码，不能填另一个 ref 的 SHA |
| `unsigned_only` | `true` | 当前仓库没有苹果签名材料 |
| `skip_tests` | 仅打包时 `true` | 不额外构建模拟器、不跑旧布局检查 |

工作流使用 `xcode-27` / Apple Silicon，校验 iOS 27 SDK；普通 GitHub 账号未必有相同 runner 和额度。先 `npm ci`、`native:build`、`cap sync ios`，再用 **App** scheme 构建设备归档。

产物：`flighty-everything-ios-arm64-unsigned.ipa`。**未签名 IPA 不能直接在标准 iPhone 安装**，需要合法适用的证书/描述文件和自行签名流程，不是 App Store / TestFlight 包。工作流支持仓库签名 secrets，但交付不提供证书或账号。

在 Mac 手动构建：

```sh
npm ci
npm run ios:sync
npx cap open ios
```

必须在 Mac 重新同步 SPM 路径，不要复制 Windows 生成的原生缓存。应用 ID：`com.wankun824.flightyeverything`。设备包和 Simulator `.app` 不可互相改名替代。核对 `App.app/Info.plist` 和 `App.app/public/build-info.json`，以内部版本/源码为准，而非历史文件名。

## 5. 各页面 iOS 截图

使用 **Capture iOS Pages on Xcode**：`source_sha` 填目标分支完整 SHA，`appearance=both` 在独立 runner 上采集浅/深两套。两个 artifact 分别为 `fly-everything-ios-page-captures-light` / `-dark`。支持只补采一种外观；`page_keys` 可填写逗号分隔的失败页面 key，只重跑这些页面（空值为全量）。

采集的是 **实际运行的 iPhone 17 Pro 模拟器像素**：借助仅限模拟器、显式开启的页面导航助手，进入 32 个现有页面/状态，再由 `simctl` 截图。原始 PNG、SHA-256、源码、主题、前台响应和视口清单一起保存。不是网页截图、设计稿或实体 iPhone 拍摄，也不等于触摸、键盘和业务提交验收。

只要一页未完成，就明确标注；不能用历史图或另一种外观替代。`merge-captures.py` 可合并多个批次，只允许替换失败项；不同提交必须校验清单中全部应用源码树相同，并保留原始清单及各图实际来源。合并后用 `ios/qa/document-captures.py` 生成逐页说明，再用 `ios/qa/verify-captures.py` 校验。具体见 [截图工具说明](../ios/qa/README.md)。

## 6. 源码、文档和 Web 包

**Package Web Build** 支持可选 `source_sha` 校验，依次执行生产构建/测试、TypeScript、原生 Web 资源构建，再输出：

- `flighty-everything-web-<sha>.tar.gz`：Web `dist/`、原生 Web 资源和运行依赖描述等，用于检查构建产物；**不是 IPA/APK，也不是独立部署工具箱**。Worker/D1 部署请使用完整源码与目标环境配置。
- `flighty-everything-0.3.2-source-<sha>-<timestamp>.zip` + `.sha256`：完整可重建源码、文档、截图、工程和依赖锁。
- `flighty-everything-docs-screenshots.zip`：独立文档与截图包。

源码打包与校验也可本地执行：

```sh
python scripts/package-source.py
python scripts/package-source.py --verify release/source/<生成文件名>.zip
```

源码包排除 `.git`、`node_modules`、构建缓存、旧安装包和凭据，保留必须的 `build/sites-vite-plugin.ts`。内置 `SOURCE-MANIFEST.json` 逐文件记录大小与 SHA-256，外部再提供 ZIP 校验和。检测常见凭据模式不是完整安全审计。

解压后先进入包含 `package.json` 的 `flighty-everything-source/` 目录。包内没有 Git 历史；`native:build` 需要源码提交。仅在解压副本尚无仓库时运行：

```sh
git init
git add .
git add -f build/sites-vite-plugin.ts .env.example
git -c user.name="Local Source Snapshot" -c user.email="snapshot@example.invalid" commit -m "Import delivered source"
npm ci
npm test
npm run native:build
```

导入后的提交 SHA 与交付原提交不同，属于正常现象；保留 `SOURCE-MANIFEST.json` 以追溯原始来源。

### GitHub CLI 示例

先推送目标分支，再记录其完整 SHA：

```sh
SHA=$(git rev-parse HEAD)
gh workflow run ios.yml --repo wkun475-star/flighty-everything --ref build/ios-ui-20261018 -f source_sha="$SHA" -f unsigned_only=true -f skip_tests=true
gh workflow run web-package.yml --repo wkun475-star/flighty-everything --ref build/ios-ui-20261018 -f source_sha="$SHA"
gh workflow run ios-screenshots.yml --repo wkun475-star/flighty-everything --ref build/ios-ui-20261018 -f source_sha="$SHA" -f appearance=both
```

这些是 Git Bash/Mac/Linux 示例。`source_sha` 是校验参数，不会自动替你切换到另一个源码；检出版本不一致时任务应失败。下载资产后，Windows 可用 `certutil -hashfile "文件名.zip" SHA256`，Mac/Linux 可用 `shasum -a 256 "文件名.zip"`，与 Release 的 `SHA256SUMS.txt` 比对。

## 7. Web 部署与 Android

- 当前 Web 为 Workers / D1 架构，不能直接把 `dist/` 当成任意静态站点部署。`npm run start`、Workers 部署和 D1 绑定需按目标环境配置。
- GitHub Actions 构建和 Release 上传**不会自动更新已有线上演示**。旧 Sites URL、项目 ID 和 D1 占位配置不代表拥有线上部署权限。
- Android：Windows 执行 `npm run android:debug`；Mac/Linux 执行 `npm run native:build` → `npx cap sync android` → `cd android && chmod +x gradlew && ./gradlew assembleDebug`。本轮无 Android 安装包或设备验收承诺。
- 地图空白时检查网络、token、WebGL 和瓦片；原生版本不更新时检查是否重新 build → sync → archive，并查看 `build-info.json`。
