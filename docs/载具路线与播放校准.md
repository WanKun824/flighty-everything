# 载具路线与播放校准

本次范围：模型切换等待、铁路线路、选中路段的镜头缩放、当前播放速度。不调整 UI 布局、模型比例、漆色、环境光、高光或玻璃材质。

## 模型切换

- 保时捷 GLB 为 899,136 字节。原实现首次进入汽车路段才加载，随后执行 smooth → paint → curve；这个顺序保留。
- 当前模型准备完毕后，在浏览器空闲时预热后续第一种不同载具；复用准备结果，不在启动时下载所有模型。
- 路况结果刷新时复用同一个 React portal 容器，避免拆掉并重建同车型的 WebGL 画布。
- 模型首帧真正渲染后才开始路段计时；失败不自动跳过，重新选中可重试。隐藏应用期间暂停演示计时。
- 本机 Node 测得汽车 GLB 解析约 5 ms、外观处理约 93 ms，仅用于定位 CPU 开销，不能当成 iPhone 实测或性能改善百分比。

## 铁路

- 旧接口 `detailedLegs=false` 不返回线路几何；地图此前只能使用两端的大圆连线。
- 改为请求 Transitous / MOTIS 的 `legGeometry`，按返回精度解码，保存到路段的 `railGeometry` 字段。
- 地图线和载具共用 `journeySegmentPath`，按累计路程推进；顶点密集的弯道不会按顶点序号忽快忽慢。
- 校验坐标范围、端点、长度和连续性。两端点连线、稀疏长跳线、断开的步行换乘，不作为已取得的铁路轨迹。
- 实际原型联调：Zürich HB → Bern 返回 HTTP 200；IC1 2,198 个点 / 117 km，IC8 2,200 个点 / 117 km，IR16 2,362 个点 / 125 km。一个含换乘且轨迹不连续的结果保持示意状态。
- 旧行程不会凭空补出线路。东京示例目前仍没有存储铁路轨迹，详情明确显示“线路示意”。须重新查询并选择具有线路覆盖的真实列车；全球线路覆盖和精确轨道中心线并非保证项。
- 不使用汽车道路代替铁路，不新增自动批量查询。Transitous 是尽力服务，商业上线或大规模使用前须按其政策协调、自建或更换服务；本次仅轻量原型联调，不替用户更改源码许可。

来源：[MOTIS API](https://raw.githubusercontent.com/motis-project/motis/master/openapi.yaml)、[Transitous 使用政策](https://transitous.org/api/)、[数据来源及许可](https://transitous.org/sources/)。

## 镜头与速度

- 点击路段只更新地图中心，删除自动 `fitBounds`；不传 zoom、pitch、bearing。
- 自动进入下一段沿用当前缩放。用户中途自行缩放后，后续跟随也使用新的缩放；手动拖地图仍暂停跟随。
- 此规则针对行程选择与播放，机场浏览的独立定位功能不在本次修改范围。
- 默认演示时长集中在 `app/vehiclePlayback.ts`，未调整数值：飞机 18 s、火车 25 s、汽车 31 s、轮船 36 s。
- 倍速公式为“默认时长 ÷ 倍速”；例如汽车 2× 为 15.5 s。当前主界面使用 1×，没有新增速度控件。
- 演示时长不是行程实际时速、到达时间或真实实时位置。下一步可按用户指定调整每种载具时长，或另行设计按里程/真实时刻播放。

## 验证

- 自动化覆盖模型等待计时、预热顺序、缩放不变、折线解码、曲线路径采样、缺失/损坏数据降级、原生 HTTP 桥解析。
- 本地浏览器核对飞机进入汽车后有一个正常就绪的模型画布；旧火车详情正确显示线路示意。
- 网页与原生内嵌资源均构建；未进行 iPhone 真机帧率测试，本次不生成或声称已更新 IPA。
