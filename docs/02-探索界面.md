# 2 · 探索界面（地图那一屏）

这是整个项目的主体。`ExploreScreen` 在 `app/page.tsx` 约 952–1500 行，地图本体在 `MapCanvas`
（约 582–901 行）。本版 `globe` 与 `mapStyle` 都写死在 `ExploreScreen` 里（965–966 行）：
**Globe 投影常开**（`globe = true`），样式固定 `"standard"`。MapCanvas 仍保留 mercator / satellite
两套分支，改两个默认值即可切换，不需要动渲染层。

设计上三个约束贯穿全局（`globals.css` 190–209 行有完整论述）：

1. **顶栏对舞台居中**（`left: 0; right: 0; margin-inline: auto`），不是对面板居中 ——
   面板能自由拖动之后，「相对面板居中」会让顶栏跟着跳。
2. **面板有一条 82px 的保留带**（`top: 82px` = 顶栏 56px + 上下间距），面板过不去，
   代价是两者可能重叠。`panelGeometry.ts` 的 `TOP_LIMIT` 必须与这个数一致，**改一处要改两处**。
3. **添加面板是非模态的**：没有遮罩、不夺焦点，地图始终可拖可缩可点。它看起来
   就是搜索框展开的下拉（宽度位置都跟 `.globe-bar` 走）。

## 2.2 Mapbox 初始化与地图配置

`MapCanvas` 用 `useEffect` 只创建一次地图（598–738 行），依赖数组空 + `eslint-disable`。

```ts
new mapboxgl.Map({
  container,
  style: mapStyle === "standard" ? "mapbox://styles/mapbox/standard" : "mapbox://styles/mapbox/standard-satellite",
  projection: globe ? "globe" : "mercator",
  center: globe ? [132, 29] : [136, 33],
  zoom: globe ? 2.15 : 4.7,      // 首屏：整条路线 fitBounds 的实测值 ≈2.15
  pitch: globe ? 14 : 48,
  bearing: -10,
  antialias: true, attributionControl: true,
})
```

`style.load` 里做一次性的建层（612–670 行）：

- `setConfigProperty("basemap", "lightPreset", …)`：standard → `"day"`，satellite → `"dusk"`；
  `show3dBuildings` / `show3dLandmarks` 按 `globe` 关掉（Globe 下 3D 建筑和地标不显示）。
  包在 `try/catch` 里 —— 旧样式没有这些配置项时保持默认。
- `setFog`（Globe 的太空雾）：`"space-color": "rgb(4, 11, 26)"`、`star-intensity: .45`。
  注意这个 Space 色与 `.journey-globe-screen` 的径向渐变底色（`#183d66 → #07111f → #030814`）是一对，
  换底色时要一起调，否则太空和雾之间会有一条明显接缝。
- 三个 GeoJSON 源 + 八层图层（见 2.3）。
- `.map-rider` marker：`pitchAlignment/rotationAlignment: "viewport"` —— 载具不跟着地图
  俯仰旋转变形，始终正对屏幕。

**选中站点时**（882–889 行）`flyTo`：

```ts
map.flyTo({ center, zoom: globe ? 4.6 : stop.kind === "airport" ? 10.6 : 12.2,
  pitch: globe ? 24 : 58, bearing: -16, duration: 1200, essential: true, padding: cameraPadding(map) });
```

- 地球仪分支 zoom 只到 4.6 —— 城市级放大在地球仪上会出「广告牌式」的扁平贴图。
- `padding` 由 `cameraPadding(map)` 实时量 `.journey-panel:not([data-hidden])` 的实际位置
  （503–514 行）：判断面板贴哪侧，让出的 padding 上限 62%（否则宽面板会把可用视口压没）；
  窄屏直接给 bottom。面板隐藏时返回全零，地图用满整块。
- `dragstart` 立刻 `onFollowBreak()`（706 行）—— 用户一拖地图就把跟随交还给他，像导航软件那样。

## 2.3 三个 GeoJSON 源与八层图层

建层顺序就是渲染顺序（先建在下）。`ROUTE_LAYERS = ["route-halo","route-flight","route-car","route-rail","route-ferry","route-done","route-trail"]`（点击命中用）。

### 源

| 源 | 内容 | lineMetrics |
| --- | --- | --- |
| `journey` | 各段线形（mode / leg / source 属性） | **true** |
| `journey-trail` | 走过的几何，按 `done` 属性分两层 | **true** |
| `journey-stops` | 站点点集（color / index / icon / selected 属性） | 不需要 |

`lineMetrics: true` 是 `line-gradient` 的前提 —— 没有它 `line-progress` 取不到值（622–623 行注释）。
数据更新不重建地图：`paths` 变化 → `journey.setData()`（746–758 行），`stops/selected` 变化 → `journey-stops.setData()`（762–796 行）。

### 行程线（6 层 + 渐变当前段）

| 图层 | 画什么 | 关键 paint |
| --- | --- | --- |
| `route-halo` | 白色描边底（所有段） | width 7、opacity .72、blur 1.5 |
| `route-flight` | 飞机段 | `#0a84ff`，`line-dasharray: [1, 1.4]` |
| `route-car` | 汽车段 | `#ff375f`，实线 |
| `route-rail` | 火车段 | `#bf5af2`，实线 |
| `route-ferry` | 轮船段 | `#32ade6`，`line-dasharray: [.6, 1.2]` |
| `route-done` | 已走完的段 | 纯白实线 width 4.4（`done: true`） |
| `route-trail` | 当前段，渐变裁开 | `line-gradient: trailGradient(progress)`，每帧更新 |

层上过滤靠 `filter: ["==", ["get", "mode"], "flight"]` 这种按属性区分，而不是每段一个图层。

### 站点标记（3 层）

| 图层 | 画什么 | 关键 paint |
| --- | --- | --- |
| `stop-ground` | 贴地光斑 | 大圆 blur .55，`circle-pitch-alignment: map` |
| `stop-anchor` | 落点小圆 | 白描边，`circle-pitch-alignment: map` |
| `stop-pin` | 国旗符号 | `icon-image: ["get","icon"]`，`icon-anchor: bottom` |

两个 circle 的 `circle-pitch-alignment: map` 让它们跟着俯仰旋转一起变形，**是真的印在地面上**
而不是浮在屏幕上的圆。`stop-pin` 是 symbol 图层，图标就是 sprite 里那枚国旗牌
（634–661 行注释说得很清楚：换成 DOM marker 就成了浮在画布上方的一层，遮挡、排序、
地球背面裁剪全都对不上）。`allow-overlap` + `ignore-placement` 保证站点挨得再近也不被
Mapbox 的避让规则藏掉。

`icon-size` 的写法里有条硬规则：**`["zoom"]` 只能作顶层 interpolate/step 的直接输入**（651–657 行）。
所以「选中的放大 1.16 倍」没法乘在 zoom 档外面，只能把两种尺寸写进每个档的输出：

```ts
"icon-size": ["interpolate", ["linear"], ["zoom"],
  2,  ["case", ["get", "selected"], .84, .72],
  8,  ["case", ["get", "selected"], 1.02, .88],
  14, ["case", ["get", "selected"], 1.16, 1],
],
```

`symbol-sort-key` 让站点先按行程顺序叠、选中的那枚抬到最上层（`index + selected*100`）。

## 2.4 站点标记的画法：drawPin 与国旗

标记是**地图原生要素**，不是 DOM。`drawPin(color, label, flag)`（258–323 行）把一枚
「圆角牌 + 尖脚」画成位图，交给 `map.addImage` 进地图自己的 sprite：

- 白底牌子 + 尖脚合成一条路径一次 fill（分两次画重叠处投影会加深一倍）；尖脚整片留白不套站点色
  （这个尺寸下彩色尖脚会被读成吊在牌子下面的另一个箭头）。
- 站点色由旗面（没国旗时）、角标和地面上的 `stop-anchor` 交代。
- 图标名是**内容哈希**：`pin:${label}:${stop.color}:${stop.country}` —— 同一个国家、颜色、
  序号只画一次，换行程也能复用。改颜色、改国家、删站点都会换出新的图标名；
  先换数据再回收 `map.listImages()` 里不再用到的 `pin:*` 图（790–794 行），顺序不能反。
- **国旗异步**：先挂纯色 + 序号占位版（`addImage` 立即生效），`flagBitmap(country)` 从
  flagcdn 取图到货后 `updateImage` 换掉 —— 前后尺寸必须一致（Mapbox 要求），占位与成品
  共用同一套 `PIN` 尺寸常量。有国旗时序号挪到右上角标（白描边实色圆）。
- `PIN = { width: 38, height: 38, plate: 30, radius: 9, border: 2.4, scale: 3 }`。

点击处理优先级（672–706 行）：`stop-pin` 命中 → 选中该站；`ROUTE_LAYERS` 命中 → 逐顶点找最近点
`onSeek(leg.from + (leg.to - leg.from) * t)`（行程线本身也是可交互控件）；空白 → picking 时才
`onMapPoint`。**点标记的那一击归标记**，不再顺带 seek 或落新点（`pinAt` 前置检查）。

## 2.5 逐帧驱动：载具、航向低通、轨迹渐变、跟随

这是整个探索屏最核心的一段（798–880 行），一帧里做的事：

```ts
const { legIndex, legProgress } = locate(liveTimeline, progressRef.current);   // 全程进度 → 段
const { coordinate, bearing, lineProgress } = sampleAt(path, legProgress);     // 位置/航向/刻度，同一次采样
riderRef.current?.setLngLat(coordinate);                                       // 命令式，不经 React

// 屏幕航向 = 真实方位角 − 地图旋转角（地图转的时候机头才不会跟着歪）
const screenHeading = (bearing - map.getBearing() + 360) % 360;
// 指数低通，收敛速率 HEADING_SMOOTH（见下）
smoothHeading = (smoothHeading + toward * (1 - Math.exp(-delta * HEADING_SMOOTH)) + 360) % 360;
// 转过 2° 才 setState → Vehicle3D 收到新 heading（Three 内部再做插值）
if (path.mode !== publishedKind || turned > 2) setRider({ kind: path.mode, heading: smoothHeading });

// 换段才上传 trail 几何（已走完标 done，当前段留给渐变裁）
// 每帧 setPaintProperty("route-trail", "line-gradient", trailGradient(lineProgress))
// follow 时 center 按 .06 插值后 jumpTo（快段慢段都不甩镜头）
```

三个设计决策值得记住：

1. **一帧内同一次采样。** 位置、航向、轨迹刻度出自同一次 `sampleAt`，轨迹边缘才会
   严格咬在载具身上（823 行注释）。
2. **为什么先低通再比阈值。** `sampleAt` 的 bearing 是逐段常量，而 driving 路线顶点密到
   几米一个 —— 原始信号是一串带噪的台阶。靠大阈值滤噪的话载具会按整数度一格一格
   「弹」着转，Vehicle3D 又把每帧的收敛速度当转向角速度去算侧倾，于是每弹一下车身跟着
   侧一下。所以滤噪交给滤波、阈值只负责少推 setState（829–832 行）。
3. **`delta` 截断 50ms**：切走标签页再回来 `now` 会跳一大截，不截断航向滤波一帧收敛完（815 行）。
   播放时钟里同样截断 250ms（见文档 3）。

### HEADING_SMOOTH = 5 的量测背书

注释（516–527 行）记录了完整的仿真 + 实拍双段验证，是「手感参数必须实测」的样板：

- 模拟一条 4km、10m 一个顶点的 S 形公路（逐段 bearing 噪声 σ≈10.8°/顶点）：
  8/s 配 turn 14 的偏航角加速度峰值 59.6 rad/s²，5/s 配 turn 9 降到 28.7 —— 少一半；
  相对理想中心线的跟随滞后 p95 只从 3.40° 涨到 3.61°，看不出。不滤波直接上 raw 反而更差
  （p95 6.96°，车头在追噪声）。
- 实拍复核：同一段 22km 公路各跑两轮，页面内挂 rAF 采样器读车身主轴角（7 秒窗口、
  均匀 60Hz 重采样再差分），8/s+14 是角速度峰值 388/360°/s、角加速度 RMS 1372/1572°/s²，
  5/s+9 降到 189/185°/s 和 681/783°/s² —— 同样正好减半。

### trailGradient：一帧一次 setPaintProperty 的取舍

```ts
const trailGradient = (progress: number) =>
  ["interpolate", ["linear"], ["line-progress"],
    0, "#ffffff",
    cut, "#ffffff",
    cut + .001, "rgba(255,255,255,0)",
    1, "rgba(255,255,255,0)",
  ];
```

`cut` 夹在 .002–.998。**输入必须是 `sampleAt` 给的 `lineProgress`**（墨卡托刻度，逐段按累积
投影距离线性），不是全程进度 —— 用它的话每段渐变的前进速度会不一样。

原来是隔帧更（省一半重绘），但那样轨迹边缘只有 30Hz、载具是 60Hz，边缘会周期性地落后
半帧，快段上看得出来在「追」。改成每帧更：一次 `setPaintProperty` 只是换一张 256px 的渐变
纹理，顶点不重传，这个开销换得值（859–862 行注释）。

## 2.6 缩放 → 速率与载具尺寸

两个量都由 `zoom` 事件驱动（`syncZoom`，710–728 行），但**完全分开**：

| 量 | 公式 | 更新策略 | 消费方 |
| --- | --- | --- | --- |
| 世界速率折算 | `zoomRate(zoom) = clamp(2^(-(zoom−4.7)·.3), .25, 2.5)` | ref **每帧**写，state 只在该变化 >4% 时发布（否则一次 flyTo 连推上百次 setState） | 播放时钟每帧读 ref |
| 载具屏幕尺寸 | `riderScale(zoom)`（见下） | 只在该值变化时写 `--rider-zoom` 到 marker 宿主元素，不经 React | CSS 变量 |

`zoomRate` 的语义：地图放大一级，同样的地表速度在屏幕上就快一倍，街道级下载具会一闪而过；
所以让世界速度反着随缩放走，屏幕上的位移速度大致稳定。指数取 .3 而不是 1（完全补偿
`2^-(z-4.7)` 从地球仪到街道跨十级就是一千倍），两头再夹 0.25..2.5（302–303 行注释）。

`riderScale` 与 `--rider-zoom`（553–556 行 + globals.css 379 行）：

```ts
const riderScale = (zoom: number) => {
  const t = Math.min(1, Math.max(0, (zoom - 5) / 8));
  return Math.round((1 - t * .25) * 20) / 20;
};
```

- 载具是**屏幕空间的固定尺寸元素**（`.map-rider` 的宽 = `calc(96px × var(--rider-zoom))`），
  地图放大它并不跟着放大 —— 但视野在缩小，同一辆车在地球仪上是小点、街道级比整条路都宽。
  拆成 `--rider-w` 和 `--rider-zoom` 两个变量，是为了让窄屏媒体查询只改基准宽度、
  不必知道缩放这一层。
- 实测阶梯（键盘逐级放大，读 CSS 变量与实际像素）：**≤5 → 1.00（96×72px）· 6~7 → 0.95 · 8~9 → 0.90 · 10 → 0.85 · 11~12 → 0.80 · ≥13 → 0.75（72×54px）**，单调无回跳。
- 起点定在 5：应用自己的机位从不超过它（首屏 ≈2.15、选中站点 4.6），挂载和点站点时
  不会跳尺寸；只有用户自己放大到城市/街道级才进收缩区间。
- 量化到 0.05 一档是必要的：每变一档 Vehicle3D 的 ResizeObserver 就要重设渲染尺寸并重算机位，
  而一次 flyTo 连推上百个 zoom 事件。25% 摊到 0.05 正好五档，平均两级缩放才跳一档
  （单档 4.8px 在连续缩放里读不出来）。
- 幅度定 25% 是改过的：第一版收到 0.58（42% 跨度）试出来「有点小了」，收太狠就从
  「贴在路上的车」变成「路上的一个小图标」，且 42% 摊在 8 级里，尺寸自变这件事反而显眼。
  现在总跨度 25%、地板 0.75：够让开路口，又还是同一辆车。

## 2.7 播放器与倍速（无级、无数字）

- 1× 基准 = **全程 329 秒**（`PLAYBACK_SECONDS`，见文档 3）。这个值是从最初的 46 秒
  重定到 230、又按「0.7 才顺眼」重定到 329 的（等于最初版本的 0.14 档）—— 改它等于改全部手感。
- 滑块 `step="any"` 无级，范围 0.1–2.0。**界面上没有任何数字**：读数在 `title` 和
  `aria-valuetext`（`speedLabel`，`1×` 显示成 `1×` 不是 `1.00×`）。
- 方向键自接 0.05 步进并 `stopPropagation`（不触发窗口级切段快捷键）；双击整格回 1×（比拖回去准）。
- 拖进度条：`pointer capture`，按下暂停、松手恢复原来的播放状态（1264–1270 行）。
- 时钟模式：预览动画 / 真实时间（按出发到达时间把当前时刻映射到进度，500ms 轮询，见文档 3）。
- live 模式下进度条和倍速禁用（`locked` 类），因为位置由真实时间决定。

## 2.8 快捷键（窗口级）

`useEffect` 挂一个 `keydown`（1272–1295 行），顺序敏感：

| 键 | 动作 | 备注 |
| --- | --- | --- |
| `Escape` | 关添加面板 | **放在输入框早退之前**：面板一打开焦点通常就在搜索框或日期框里，早退掉就按不动了 |
| `Space` | 播放/暂停 | live 模式禁用；焦点在 `BUTTON/A/SUMMARY` 上时不抢（那是按钮自己的激活键） |
| `← / →` | 上一段 / 下一段 | 后退先回本段起点（`stepLeg`，阈值 .02），已经在起点才真退一段 |
| `F` | 切换镜头跟随 | 顶栏按钮同款（`aria-label="镜头跟随载具（F）"`） |
| `J` | 面板显隐 | 隐藏后 `.panel-restore` 复位钮还在原位 |

在 `INPUT/TEXTAREA/SELECT` 或 `contentEditable` 里一律早退。

## 2.9 添加地点（搜索 + 地图选点）

**搜索框是全站唯一一个**（1309 行），聚焦即 `setAdding(true)`，打过的字直接就是 query——
没有第二个输入框，也不用把字倒过去。面板是非模态的（见 2.1）。

- 检索：300ms 防抖 + `AbortController` + `queryVariants` 并发 + `rankHits` 汇总（见文档 6）。
  单个请求挂了只当它返回空，不拖垮其他路（1073 行）。

  Geocoding 结果已带坐标。retrieve 顺手带回国家码，能省掉 commitStop 里那次反查（1121–1149 行）。
- 地图选点：`pickingOnMap` 打开后地图出现 `is-picking` 提示条（globals.css 603 行），
  点空白处 → `onMapPoint` → reverse geocode 出草稿卡（`selectMapPoint`，1151–1174 行）；
  没有「确认」按钮，点出草稿直接就是待提交状态。关闭面板会清掉草稿（`closeAdding`）。
- 提交（`commitStop`）：国家码缺失时 `resolveCountry` 补一次反查 —— 站点先落地、旗子后到，
  加站不该被网络请求卡住（1106–1113 行）。session token 每次提交后轮换（Mapbox 计费要求）。
- 交通方式选择用**图标格子**（`.vehicle-picker`，四个 26×52 图标），不放 3D 模型；
  `.fleet-grid`（面板「载具」分段的 3D 展厅）是**唯一合法的 3D 展示位**（globals.css 364–373 行）。
- 删除少于两站的站会直接拒绝（`removeStop`，1239–1244 行）；`setLegMode` 改的是「从这站
  出发怎么走」，所以改的是这一段。

## 2.10 面板的相机让位与窄屏联动

- `cameraPadding`（见 2.2）是「面板挡哪、flyTo 让哪」的唯一来源，靠实时量 DOM 而不是存状态。

## 2.11 已知口径差异（接手前必须知道）

`routeRules.ts` 把火车声明为 `engine: "geodesic-corridor"`、`geometry: "rail-corridor"`，
但 `useJourneyPaths` 对 `train` 段**同样请求 Mapbox driving**（`if (leg.mode !== "car" && leg.mode !== "train") continue;`）。
于是：

- 火车段的 `path.source` 可能是 `"road"`（拿到了路网）或 `"geodesic"`（失败了）；
- 面板标签（`routeRuleFor(mode).geometry` 那一路，1374 行附近）仍显示「铁路走廊规则」；
- 文档 3 的 `RAIL_NOTE` 说得直白：这是**用真实陆路走廊近似轨道走向** —— 形状仍来自真实
  基础设施，但不是真实轨道中心线，因为 Mapbox Directions 没有 rail profile。

这不是 bug，是刻意的近似，但改 `routeRules.ts` 或 `routeGeometry.ts` 时两边的口径必须一起改，
不然标签与几何会继续脱节。
