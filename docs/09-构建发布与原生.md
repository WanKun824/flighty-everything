# 9 · 构建发布与原生打包

发布/打包的完整操作步骤在根目录 `HANDOFF-20260814.md`（第 6–9 节），这份只讲**机制**。

## 9.1 部署目标

三个交付物，**同一个 Web 产物**：

| 交付物 | 怎么出 | 加载什么 |
| --- | --- | --- |
| 网页 | `.openai/hosting.json` 绑定，构建后发布到线上地址 | 自己 |
| Android APK | GitHub Actions `Build Android APK` | **Capacitor 容器 + 线上站点 URL** |
| iOS IPA | GitHub Actions `Build iOS IPA` / Codemagic | 同上 |

关键点：**原生容器不打包前端**。`capacitor.config.ts` 的 `server.url` 指向生产地址，
所以网页每次发布，App 打开就是新版，不需要重新打包 —— 发布门槛（`npm ci && lint && test`）
就是为这个契约设的（HANDOFF 第 9 节）。

## 9.2 GitHub Actions

| 工作流 | 触发 | 跑什么 | 时长限额 |
| --- | --- | --- | --- |
| `ci.yml` | push main / PR / dispatch | `npm ci` → lint → `npm test`（`NEXT_PUBLIC_MAPBOX_TOKEN` 走 secret） | 15min |
| `android.yml` | dispatch / `v*` tag | `npm ci` → `cap sync android` → gradle `assembleDebug` → 传 APK artifact（14 天） | 30min |
| `ios.yml` | dispatch | macOS 26（Capacitor 8.5 要求 Xcode 26）→ 签名/免签名 → 产出 `manyou-unsigned.ipa` 或签名 IPA | — |

**用量纪律**：私有仓库的 macOS 分钟倍率高于 Linux，所以 iOS 工作流**只手动跑**；
push 只触发 Linux CI。用量在 GitHub 头像 → Settings → Billing → Usage 看。

iOS 签名需要 5 个 Secret（`IOS_CERTIFICATE_BASE64` / `IOS_CERTIFICATE_PASSWORD` /
`IOS_PROVISIONING_PROFILE_BASE64` / `IOS_KEYCHAIN_PASSWORD` / `IOS_TEAM_ID`）；
Bundle ID 固定 `com.wankun824.manyou`，证书与描述文件必须匹配。不配置签名时产出
未签名 IPA（可交签名服务或重签）。

## 9.3 Codemagic（个人版）

`codemagic.yaml` 在根目录，可被 Codemagic 个人版读取，默认产出未签名 IPA。
与 Actions 的 ios.yml 二选一，别两处都维护两套不同的签名逻辑。

## 9.4 Capacitor 壳

- `webDir: "native-shell"` —— 那个目录只是占位（`native-shell/`），真正内容是远程 URL。
- `cleartext: false` + `androidScheme: "https"`：只走 HTTPS；Android 上 `allowMixedContent: false`。
- iOS `contentInset: "automatic"`、背景色 `#F8F8FA`（Android `#F9F9FF`）—— 和 Web 端
  `--content` 令牌一致，避免原生壳底色与页面有缝。
- `npx cap sync` 把 webDir 与原生工程同步；改 `capacitor.config.ts` 后必须重新 sync。
